# MCN 闭环分析流程（阶段 8-9）

**版本**: 1.0.0
**更新**: 2026-04-23

---

## 概述

闭环分析是 MCN 流程的反馈阶段，通过数据采集和对比分析，持续优化内容生成质量。

**执行方式**: 定时任务（每日 21:00）

**输出**: 优化建议 → 反哺阶段 4 的改写提示词

---

## 阶段 8：数据采集

### 8.1 已发布文章数据

使用 `wechat-analytics` 技能获取：

| 指标 | 说明 | API 接口 |
|------|------|----------|
| read_count | 阅读数 | articles/statistics |
| like_count | 点赞数 | articles/statistics |
| favorite_count | 收藏数 | articles/statistics |
| share_count | 转发数 | articles/statistics |
| comment_count | 评论数 | articles/statistics |

**采集时间点**: 发布后 7天/15天/30天

### 8.2 原文数据（直接读取本地）

**⚠️ 预抓取机制**：原文数据在选题阶段（阶段2）已预抓取，直接读取本地文件即可。

**数据位置**：
```
mcn/topic/{date}/sources/topic-{idx}/
├── source.json      # 原文完整数据
├── source.html      # 原文HTML（备用）
└── competitors.json # 竞品文章列表
```

**读取示例**：
```python
# 根据已发布文章找到对应的选题日期和索引
source_path = f"mcn/topic/{date}/sources/topic-{idx}/source.json"
with open(source_path) as f:
    source_data = json.load(f)

# 原文数据已包含：
# - title, url, platform, author
# - content（完整正文）
# - metrics（阅读/点赞/收藏/转发）
# - keywords, snippets
```

### 8.3 竞品数据（直接读取本地）

**数据位置**：
```python
competitors_path = f"mcn/topic/{date}/sources/topic-{idx}/competitors.json"
with open(competitors_path) as f:
    competitors_data = json.load(f)

# 竞品数据已包含：
# - articles（top 5-10 竞品文章）
# - 每篇包含：title, url, platform, metrics, style_tags, title_type
```

### 8.4 数据采集流程

```
1. 获取已发布文章列表（wechat-analytics）
2. 根据文章标题匹配对应选题日期/索引
3. 直接读取本地 source.json（原文数据）
4. 直接读取本地 competitors.json（竞品数据）
5. 对比当前数据 vs 原文抓取时的数据（可选：重新抓取更新数据）
```

## 阶段 9：对比分析

### 9.1 数据对比

**对比维度**:

| 对比项 | 公式 | 目标 |
|--------|------|------|
| 阅读差距 | our_read / source_read | 分析标题吸引力 |
| 点赞率 | like_count / read_count | 分析内容质量 |
| 转发率 | share_count / read_count | 分析传播性 |
| 收藏率 | favorite_count / read_count | 分析实用性 |

### 9.2 六维度交叉分析

#### 维度 1：标题

**分析要点**:
- 长度（15-25字为佳）
- 钩子类型（数据/争议/悬念/反问）
- 情感词（焦虑/好奇/共鸣）
- 数字使用（具体 vs 模糊）

**优化目标**: 标题竞选评分规则

#### 维度 2：内容

**分析要点**:
- 段落结构（总分总 vs 递进式）
- 信息密度（干货比例）
- 深度（表面 vs 深挖）
- 代码/图表使用

**优化目标**: 改写模板结构

#### 维度 3：写作风格

**分析要点**:
- 口语化程度（"我觉得"/"其实"/"说白了"频率）
- 专业术语比例
- AI痕迹词汇（"综上所述"/"由此可见"）

**优化目标**: 去 AI 化规则调整

#### 维度 4：表达方式

**分析要点**:
- 故事化（案例引入）
- 数据化（统计数据支撑）
- 观点化（个人立场）

**优化目标**: 文风偏好设定

#### 维度 5：排版

**分析要点**:
- 图片数量和位置
- 列表使用频率
- 分段长度（200-400字为宜）

**优化目标**: 排版模板调整

#### 维度 6：引流话术

**分析要点**:
- 结尾引导（关注/点赞/转发）
- 互动提问
- 话题延伸

**优化目标**: 固定尾部优化

## Pitfalls

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 原文 URL 找不到 | 文章未记录来源 | 搜索标题关键词查找 |
| 竞品数据不完整 | 平台限制抓取 | 多平台交叉验证 |
| 优化建议泛泛而谈 | 分析不够深入 | 基于具体数据案例 |
| 提示词更新后效果不佳 | 优化方向错误 | 小步试错，观察效果 |
| sources 目录不存在 | 阶段2预抓取未执行 | 需手动创建并补充抓取脚本 |
| 微博热搜抓取失败 | 微博需登录验证 | 使用已登录的 web-fetcher 页签或跳过 |
| 深度文章压缩过度 | 改写模板字数限制 | 深度分析类保持原文80%以上篇幅 |
| 标题缺乏差异化 | 与原文标题高度相似 | 添加情绪词/疑问句/数字钩子 |
| 副标题模板化 | 每篇都用"数据揭示了什么" | 根据文章类型定制副标题 |

## 实际执行发现（2026-04-26）

### 深度压缩问题

**数据对比**:
| 文章 | 原文长度 | 改写后长度 | 深度比 |
|------|---------|-----------|--------|
| 月暗DeepSeek | 4,971字 | 2,308字 | **46%** (严重压缩) |
| 黄仁勋GPT-5.5 | 2,946字 | 2,344字 | **80%** (轻度压缩) |

**结论**: 深度分析类文章（36kr长文）不应过度压缩，需保持原文80%以上篇幅，否则丢失关键洞察。
