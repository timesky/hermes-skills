# MCN 内容生成

根据选题生成公众号文章（1500-2000字），自动调用 humanizer-zh 去 AI 化。

---

## 功能闭环与产出交付

**职责**：独立完成内容生成阶段所有工作。

| 项目 | 说明 |
|------|------|
| 输入 | `--topic {选题标题}` |
| 产出位置 | `mcn/content/{date}/{slug}/article.md` |
| 产出要求 | 1500-2000字，去AI化完成，相似度<30%（网络来源），深度保持验证 |
| 状态返回 | `{"status": "success", "output_path": "...", "topic_slug": "...", "word_count": ...}` |

**衔接机制**：
- 下游技能 `ai-image-generation` 使用相同 `topic` → 配图产出到同目录 `images/`
- 不需要参数传递，约定优于配置

**验证要求**：
- 字数达标（1500-2000）
- 相似度 <30%（网络来源文章）
- 深度保持验证（核心信息保留）
- 案例保留验证
- 去 AI 化完成

## 标题生成公式（融合 baoyu-title-formulas）

### 8 种 Hook 公式

| # | 公式 | 特点 | 适用场景 | 示例 |
|---|------|------|----------|------|
| 1 | **颠覆型** | 否定主流认知，制造冲突 | 挑战主流建议、辟谣 | "别问哪个大模型最强了，答案根本没有" |
| 2 | **解决方案型** | 直接给出价值承诺 | 实操指南、教程 | "用这6个模型组合，一年省3万" |
| 3 | **悬念型** | 信息差，引发好奇 | 个人经历、案例研究 | "DeepSeek的定价，让同行睡不着觉" |
| 4 | **具体数字型** | 数字增加可信度 | 数据驱动、步骤指南 | "实测5款大模型30天，这份指南送给你" |
| 5 | **对比型** | 小投入大结果 / 预期反转 | 前后对比、意外发现 | "Claude贵10倍，但我们还在用它" |
| 6 | **结果先行型** | 惊人结果倒推原因 | 成功案例、转变故事 | "DeepSeek读完500行遗留代码，指出了3个Bug" |
| 7 | **反问型** | 直击痛点 | 问题意识、诊断内容 | "为什么你的大模型选型还在踩坑？" |
| 8 | **共情型** | 触发共鸣 | 痛点叙述、社区共情 | "大模型太多选不过来？这份实测指南帮你" |

### 标题原则

| 原则 | 说明 |
|------|------|
| **Hook 在前5字** | 信息差或认知冲突必须尽早出现 |
| **具体 > 抽象** | "150行" > "一个文档" |
| **否定 > 肯定** | "你做错了" > "正确的方法" |
| **对话感** | 像和朋友聊天，不是学术论文 |
| **上限 ~30字** | 超长标题在信息流中被截断 |
| **准确不标题党** | 内容必须兑现标题承诺 |

### 禁止模式

| 类型 | 错误示例 |
|------|----------|
| 学术风 | "关于XX的思考"、"XX的探索与实践" |
| 纯震惊 | "震惊！"、"万字长文"、"必收藏" |
| 无方向提问 | "AI写作的未来在哪里？" |
| 模板副标题 | "数据揭示了什么"、"什么值得注意"（扣分 -20） |

### 标题生成流程

1. **分析选题内容**：识别核心价值、痛点、数据
2. **选择公式**：根据内容类型选择 2-3 个适用公式
3. **生成候选**：每个公式生成 1-2 个标题（共 4-6 个）
4. **评分排序**：按原则评分（Hook位置+5分、具体数字+3分、否定形式+2分）
5. **选择最佳**：得分最高者作为最终标题

## ⚠️ 相似度与深度保持（重要区分）

**两个要求看似冲突，实则不矛盾**：

| 要求 | 标准 | 目的 | 验证方式 |
|------|------|------|----------|
| **深度保持** | 核心信息保留率 ≥80% | 保持内容价值 | 案例/数据/观点是否保留 |
| **相似度** | <30%（网络来源） | 防抄袭/侵权 | 措辞表达不重复 |

### 关键区分

```
❌ 错误理解：深度保持 = 字数比例 ≥80%（会导致相似度高）
✅ 正确理解：深度保持 = 核心信息保留（案例骨架），表达方式原创
```

### 改写策略示例

```
原文："Dan Shipper做了一个实验，他的App上线后出了一个顽固bug，
      请了一位顶尖工程师来重构，花了几天才搞定。"

改写："AI平台Every的创始人Shipper曾遇棘手bug，高手工程师数日才解决。
      这说明AI工具也会出人意料的难题。"
```
→ **案例保留**（深度✅），**表达全换**（相似度低✅）

### 原创创作场景

**无原文依赖时**（微博需登录、虎嗅需JS渲染等无法抓取）：
- 基于话题本身进行原创评论思考
- 不引用原文措辞
- **相似度自然<30%**，自动满足合规要求

## 案例保留验证（新增）

**触发条件**：存在原文数据

**提取模式**：
| 模式 | 示例 |
|------|------|
| 实验案例 | "有一次..."、"XXX做了一个实验" |
| 人物引用 | "XXX也有类似经历"、"XXX说：" |
| 公司/人名 | Dan Shipper、黄仁勋、OpenAI、英伟达等 |

**判断标准**：
- 案例保留率 ≥ 80% → 通过
- 缺失关键案例 > 2 个 → 提示补充

## Pitfalls

| 问题 | 解决方案 |
|------|----------|
| **标题模板化副标题** | "数据揭示了什么"、"什么值得注意" 等模板副标题已被加入扣分项（-20分） |
| **相似度超标** | 网络来源文章相似度必须<30%。改写策略：保留案例骨架→重写表达方式→补充个人视角 |
| **案例缺失** | 原文具体案例（人名/公司名/事件）必须保留。步骤6自动检查 |
| **无原文数据时跳过验证** | 若 `sources/source_articles.json` 不存在，验证自动跳过 |
